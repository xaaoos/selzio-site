# AI‑напарник SELZIO

Публичный AI‑напарник работает через локальный Node.js API:

- `POST /api/agent` — диалог через OpenAI Responses API;
- `POST /api/consultation` — отправка заявки в Telegram;
- `GET /api/health` — состояние конфигурации без раскрытия секретов.

## Настройка

1. Скопировать `.env.example` в `.env`.
2. Заполнить `OPENAI_API_KEY`.
3. Создать Telegram-бота, добавить `TELEGRAM_BOT_TOKEN` и идентификатор чата `TELEGRAM_CHAT_ID`.
4. Перед запуском загрузить переменные окружения удобным для сервера способом.
5. Запустить `npm start`.

Для публичного трафика используется `gpt-5.6-luna`. Модель можно заменить через `OPENAI_MODEL` без изменения кода.

API-ключи никогда не передаются в браузер. Незавершённые диалоги не сохраняются на сервере. В памяти процесса хранится только временный счётчик запросов для ограничения частоты.

На production Nginx должен продолжать отдавать статические файлы и проксировать `/api/` на локальный порт приложения.

## Поведение интерфейса

- Виджет подключён на `index.html` и `sites.html` через общие `agent.css` и `agent.js`.
- Основная кнопка и плавающий триггер открывают один и тот же попап.
- Попап поддерживает обычный диалог, предварительную диагностику процесса и подготовку заявки.
- Прямая ссылка с `#ai-teammate` или `?agent=open` открывает виджет автоматически.
- Если Telegram не настроен, интерфейс предлагает посетителю прямой переход в Telegram вместо ложного подтверждения отправки.

## Безопасность

- Не добавлять секреты в HTML, клиентский JavaScript или Git.
- Модель получает не более 12 последних сообщений; длина входных полей ограничена на сервере.
- Запросы к AI и отправка заявок имеют отдельные ограничения частоты.
- Сервер не отдаёт скрытые файлы, `server.mjs` и сегменты путей, начинающиеся с точки.
- Вызов OpenAI выполняется с `store: false` и анонимным `safety_identifier`.

## Production

Приложение должно работать как постоянный Node.js‑процесс под менеджером сервисов. Nginx обслуживает статические файлы и проксирует `/api/` на порт из `PORT`. Проверка конфигурации доступна по `GET /api/health`; ответ показывает только наличие настроек, но не раскрывает их значения.
